# TickTask 后台管理平台 — 激活码导出功能方案

> 版本：v1（待确认）  
> 日期：2026-11-02  
> 涉及页面：管理后台 `/admin/` → 激活码管理（`#/codes`）  
> 改动范围：**仅前端单文件** `release/admin/index.html`（不改 Worker、不改数据库、不动其它页面）

---

## 一、需求回顾

在「激活码管理」页增加导出能力：

1. 点击「导出」按钮**向下展开下拉菜单**，菜单内含「导出 Excel」「导出 txt」两项；
2. 两种导出**只导出当前筛选后的数据**（不是当前页）；
3. **Excel 表头固定 8 列**：激活码、批次、备注、状态、使用者、发放时间、使用时间、创建时间；
4. **txt 只导激活码**，一码一行，无其它分隔符；
5. 成功或失败都要 toast，且提示中必须给出**成功数量 / 失败数量**。

---

## 二、现状梳理

| 项 | 现状 | 对方案的影响 |
| --- | --- | --- |
| 页面实现 | `release/admin/index.html`，原生 JS 单文件 SPA，零外部依赖/CDN | 导出能力需**内联实现**，不能引第三方库 |
| 列表接口 | `GET /api/admin/codes?q=&status=&page=&pageSize=`，`pageSize` 服务端上限 **200** | 导出"筛选后全量"需**前端分页拉取**，不新增接口 |
| 返回字段 | `code / batch / note / status / used_by / used_at / issued_at / created_at / user_email` | 8 列表头所需字段**全部已具备**，无需改后端 |
| 排序 | `ORDER BY created_at DESC` | 导出顺序与页面一致（新→旧） |
| 筛选条件 | 关键词 `q`（匹配 激活码/批次/备注）+ 状态 `status` | 导出复用同一套参数 |
| 现有交互 | `toast()`、`openModal()`、`.toolbar` / `.btn` 样式 | 下拉菜单需新增局部样式；toast 需支持更长展示时长 |
| 缓存 | 列表有 `cacheGet/cacheSet`（先缓存后同步） | **导出不复用缓存**，直连接口取最新数据，避免导出脏数据 |
| 静态缓存 | `server.js` 对 `.html` 已设 `no-cache` | 改完重新部署即可生效，无需额外版本号 |

## 三、交互设计

### 3.1 入口位置

放在列表**工具栏右侧**，「发放选中」按钮左侧：

```
[搜索激活码/批次/备注]  [全部状态 ▾]                    [导出 ▾] [发放选中] [删除选中]
```

理由：导出的是"筛选后的数据"，与筛选控件同一行语义最近，也不会与页头的「+ 批量生成激活码」抢视觉焦点。

按钮形态：`导出` + 向下箭头 `▾`，点击后箭头旋转 180°，按钮呈激活态（浅蓝底）。

### 3.2 下拉菜单

- 位于按钮正下方，**右对齐**，宽度 200px，白色卡片 + 阴影 + 8px 圆角，`z-index: 60`；
- 两项，每项两行（主标题 + 灰色副说明）：
  - **导出 Excel** — `8 列完整字段，.xlsx`
  - **导出 txt** — `仅激活码，每行一个`
- 交互：再次点击按钮收起；点击页面其它任意位置收起；按 `Esc` 收起；选择任一项后立即收起；
- 无障碍：按钮 `aria-haspopup="menu"`、`aria-expanded`，菜单项 `role="menuitem"`。

### 3.3 导出中状态

导出期间（拉取数据阶段）：按钮禁用，文案变为 `导出中 40%`，下拉不可再打开；完成后恢复。防止重复触发产生多份重复下载。

## 四、数据获取策略

**口径**：`q` + `status` 当前值 → 该筛选条件下的**全部记录**（跨页），忽略列表勾选。

流程：

1. 先取页面已知的筛选总数 `total`（列表最近一次加载结果）。若 `total === 0` → `toast('当前筛选下没有可导出的数据')`，**不生成文件**；
2. 以 `pageSize=200` 从第 1 页起**串行**拉取（串行避免触发限流、避免顺序错乱），每页更新按钮进度百分比；直到累计条数 ≥ `total` 或某页返回空；
3. 拉取完成后统一生成文件并触发下载。

**保护上限**：单次导出最多 **20000 条**。超过时不导出，提示 `数据量过大（共 N 条，上限 2 万），请缩小筛选范围`。按当前数据规模（千级）正常不会触发，仅作为浏览器内存/卡顿的兜底。

**一致性**：导出过程中不做列表刷新；若服务端数据在此期间变动，以导出开始时拉到的 `total` 为基准，多退少补不影响文件可用性。

## 五、Excel 导出设计

### 5.1 列定义

| 列序 | 表头 | 取值 | 格式规则 |
| --- | --- | --- | --- |
| A | 激活码 | `code` | 原样文本（强制文本类型，不会被 Excel 当公式） |
| B | 批次 | `batch` | 空 → 空单元格（不写 `—`） |
| C | 备注 | `note` | 空 → 空单元格；保留原文 |
| D | 状态 | `status` | 映射中文：`unissued→未发放`、`issued→已发放`、`used→已使用` |
| E | 使用者 | `user_email` | 未使用时为空单元格 |
| F | 发放时间 | `issued_at` | `YYYY-MM-DD HH:mm`（浏览器本地时区，与页面 `fmtTime` 一致）；空 → 空 |
| G | 使用时间 | `used_at` | 同上 |
| H | 创建时间 | `created_at` | 同上（必有值） |

### 5.2 工作表细节

- 文件名：`激活码_<全部|未发放|已发放|已使用>_<YYYYMMDD-HHmm>.xlsx`，例如 `激活码_已发放_20261102-0956.xlsx`；
- 表头行加粗、浅灰底、**冻结首行**、开启**自动筛选**，方便运营二次处理；
- 列宽：激活码 20、批次 14、备注 32、状态 10、使用者 26、三个时间列各 18；
- 时间以**文本**写入（非日期序列号），避免时区换算误差，Excel 中可直接阅读、筛选、排序。

### 5.3 技术实现（零依赖）

后台是"单文件零 CDN"，不引入 SheetJS，改为**内联一个约 130 行的极简 xlsx 生成器**：

1. 拼 `[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、`xl/_rels/workbook.xml.rels`、`xl/worksheets/sheet1.xml`、`xl/styles.xml`；
2. 单元格统一用 `inlineStr`（不生成 sharedStrings，省一层映射）；
3. 手写 **ZIP（store 不压缩）** 打包：本地文件头 + 中央目录 + EOCD，需实现 CRC32；
4. 输出 `Blob`（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`）→ `URL.createObjectURL` → `<a download>` 触发下载 → `revokeObjectURL`；
5. XML 转义 `& < > " '`，并剔除 XML 1.0 非法控制字符（备注里可能出现）。

> 不压缩的代价：1 万条约 1.5MB（可接受）；收益是不用内联压缩库、体积与逻辑都可控。生成后我会用 Python（zipfile + openpyxl）实测能否正常打开、表头与行数是否正确。

## 六、txt 导出设计

- 内容：仅 `code`，`join('\r\n')` 一码一行，**末尾带一个换行**；无表头、无序号、无逗号/制表符等分隔符；
- 编码：UTF-8 **不加 BOM**（激活码为纯 ASCII，加 BOM 会让首行混入不可见字符，粘贴时出问题）；
- 换行：`\r\n`（Windows 记事本兼容性最好）；
- 文件名：`激活码_<筛选标识>_<YYYYMMDD-HHmm>.txt`。

## 七、Toast 与数量口径

### 7.1 口径定义（成功 + 失败 = 期望总数，恒成立）

- **期望总数** = 导出开始时的筛选 `total`；
- **成功数量** = 实际写入文件的记录数；
- **失败数量** = `期望总数 - 成功数量`（不小于 0）。

### 7.2 文案与样式

| 场景 | 样式 | 文案 |
| --- | --- | --- |
| 全部成功 | 绿色 `ok` | `导出成功：共 128 条，成功 128 条，失败 0 条` |
| 部分成功（拉取中途失败） | 新增琥珀色 `warn` | `导出完成：共 128 条，成功 120 条，失败 8 条` |
| 全部失败 | 红色 `err` | `导出失败：共 128 条，成功 0 条，失败 128 条` |
| 无数据 | 灰色/`err` | `当前筛选下没有可导出的数据`（不生成文件） |
| 超上限 | `err` | `数据量过大（共 32100 条，上限 2 万），请缩小筛选范围` |
| 登录过期 | 沿用现有 401 逻辑 | 跳登录页 + `登录已过期，请重新登录` |

- 导出类 toast 展示时长由 2.6s 延长到 **4.2s**（给 `toast()` 增加可选时长参数，默认值不变，不影响其它调用）；
- 失败时在第 2 行给出原因（如 `第 3 页请求失败：网络请求失败`），保证可排查。

### 7.3 部分成功时的处理

拉取中途失败时，**已取到的数据仍生成文件并下载**（不浪费已拉取结果），toast 用琥珀色明确"共 X 条，成功 Y 条，失败 Z 条"，用户可自行重试补齐。

## 八、异常与边界

| 场景 | 处理 |
| --- | --- |
| 筛选结果为 0 | 不生成文件，toast 提示 |
| 未登录 / token 过期 | 复用 `api()` 的 401 逻辑，跳登录页 |
| 网络中断、Worker 502 | 停止拉取，按"部分成功"口径出提示 |
| 浏览器拦截自动下载 | 捕获异常 → `导出失败：共 N 条，成功 0 条，失败 N 条`，并提示允许下载 |
| 用户连续点击 | 导出中按钮禁用，不会重复触发 |
| 备注含换行/引号/`&` | XML 转义 + 保留换行，不破坏文件结构 |
| 激活码以 `=`、`+` 开头（自定义前缀） | 以 `inlineStr` 写入，Excel 不会解析为公式 |
