# 下载站静态内容迁移自有 R2 —— 落地方案

> 目标：把 `sync.tuanzhang.site` / `todobar.tuanzhang.site` 的**非 `/api/` 静态内容**，
> 从「Worker 回源平台分享域 `todobar-app.app.workbuddy.host`（靠注入 sharecode 苟活）」
> 改为「Worker 直接从自有 R2 桶 `tuanzhangyinqing` 读取」。
> 从此平台发版换不换码、平台域封不封，都与对外下载站、后台、安装包无关。
>
> 不变的部分：`/api/*`（登录/同步/埋点/后台）仍走 Worker + D1；
> 对外域名仍是两个自有域；**国内可达性不变**（仍走 Cloudflare 自有域），不开 VPN 照常下载。

## 1. 目标架构

```
用户 → sync.tuanzhang.site (Worker)
         ├─ /api/*        → Worker + D1（完全不变）
         └─ 其他(静态)    → env.SITE.get(key) → R2 tuanzhangyinqing
              ├─ /        → index.html
              ├─ /admin/  → admin/index.html
              ├─ /version.json → 运行时改写 url 为本域(保留)
              ├─ /download/<file> → 写 site_downloads(D1) + 302 到 /<file>
              └─ /<file>  → R2 原对象(带 content-type/缓存头)
```

## 2. 执行步骤（每步可独立回退）

### 步骤 A — 上传静态文件到 R2（无风险，可先做，不影响线上）
Worker 此刻仍回源平台域，上传 R2 **不会**改变线上行为。传完再改代码。

需上传对象（key 即 URL 路径去掉前导 `/`）：
- 页面：`index.html`、`faq.html`、`features.html`、`compare.html`、`changelog.html`、`holidays.json`、`version.json`、`robots.txt`、`sitemap.xml`、`favicon*.png/ico`、`logo.png`、`wallpaper.jpg`、`BingSiteAuth.xml`、`googlexxx.html`、`baidu_verify*.html`
- 后台：`admin/index.html`
- 资源：`assets/*`（webp/css）、`screenshots/*`
- 安装包：`Tacco-setup.exe`、`TickTask_0.4.57_aarch64.dmg`、`TickTask_0.4.57_x64.dmg`

上传命令模板（逐个，带正确 content-type）：
```bash
CI=1 node scripts/deploy.mjs r2 object put tuanzhangyinqing/index.html --file=../release/index.html --ct="text/html; charset=utf-8"
CI=1 node scripts/deploy.mjs r2 object put tuanzhangyinqing/version.json --file=../release/version.json --ct="application/json"
CI=1 node scripts/deploy.mjs r2 object put tuanzhangyinqing/Tacco-setup.exe --file=../release/Tacco-setup.exe --ct="application/octet-stream"
# ... 其余同理
```
建议写一个 `sync-worker/scripts/upload-site.mjs` 批量传（带 content-type 映射表 + 逐对象回读校验 + 失败重试）。
**关键**：传完必须逐对象 `r2 object get` 回读，校验字节数 > 0（R2 REST list 接口对本 token 不返回数组，不能用"列表"判断成功与否）。

### 步骤 B — Worker 改造（代码，本地可验证，未部署不影响线上）

1. `wrangler.toml` 增加 R2 绑定：
```toml
[[r2_buckets]]
binding = "SITE"
bucket_name = "tuanzhangyinqing"
```
2. `src/index.ts`：
   - `import type { R2Bucket, R2ObjectBody } from '@cloudflare/workers-types'`
   - `WorkerEnv` 加 `SITE: R2Bucket`
   - 新增 `serveR2(request, pathname, env, ctx)`：把 pathname 映射到 R2 key，读对象返回；处理内容类型、缓存头、`/version.json` 运行时改写、`/download/` 归因 + 302；对象不存在返回本地 404 页。
   - `fetch()` 里把「非 `/api/` → `proxySite(...)`」改为「非 `/api/` → `serveR2(...)`」。
   - **保留** `proxySite` / `fetchSiteUpstream` / `SITE_SHARECODE` 相关代码作为应急回退开关（见步骤 E），不删除。
3. `SITE_UPSTREAM` 相关常量保留但默认不走；`rewriteVersionJsonUrl` 复用。

### 步骤 C — 单测 + 类型检查（本地）
- 新增 `src/index.test.ts` 用例：`pathname→R2 key` 映射（含 `/`、`/admin/`、`/download/`）、version.json 改写、content-type 映射、404 兜底。
- `npm run typecheck`、`npm test` 全绿。
- 用 `wrangler dev` 本地连远程 R2（`--remote`）实测几个入口。

### 步骤 D — 部署 + 验证（唯一影响线上的一步）
```bash
cd sync-worker
CI=1 node scripts/deploy.mjs deploy
```
部署后立刻验证（两域都测）：
- `curl -I https://sync.tuanzhang.site/` → 200 text/html
- `curl https://sync.tuanzhang.site/version.json` → 0.4.65 + url 指向本域
- `curl -I https://sync.tuanzhang.site/Tacco-setup.exe` → 200 + `application/octet-stream` + content-length 40690244
- `curl https://sync.tuanzhang.site/admin/` → 200（后台 SPA）
- `curl -I https://sync.tuanzhang.site/holidays.json` → 200
- `/api/health`、`/api/tasks`（401 到业务层）→ 证明 API 未受影响
- 响应头 `x-served-by: r2`（新增标识，便于确认走的是新链路）

### 步骤 E — 回退预案（一键切回）
若任一验证失败，立刻把 `fetch()` 的非 API 分支切回 `proxySite(...)`（改一个常量 `USE_R2_STATIC = false` 即可），重新 `deploy.mjs deploy`。R2 里的对象保留不动，下次再切。
回退后行为 = 迁移前（回源平台域 + 注入当前 sharecode），需确认 `SITE_SHARECODE` 仍是平台当前码。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 81MB 安装包上传慢/中断 | 逐个传 + 回读校验；exe 优先，dmg 后补；中断可续传单个 |
| 迁移后某静态文件 404 | 步骤 A 逐对象回读 + 步骤 D 全入口 curl 验证；R2 key 与 URL 严格一致 |
| 归因丢失 | `/download/` 在 Worker 内直接 `recordSiteDownload(db,...)`，写 D1；对照迁移前后 `site_downloads` 增量 |
| 国内可达性变化 | 对外域不变、仍走 CF，理论上不变；部署后在自有域实测确认 |
| 平台域彻底废弃后无处回退 | 保留 `proxySite` 代码 + `USE_R2_STATIC` 开关；平台域当前仍可用 |
| 后台 SPA 深链 404 | `/admin/` 及 `/admin/*` 统一回退到 `admin/index.html`（前端路由） |

## 4. 完成后收益

- 平台发版换 sharecode / 平台域故障 → **对外下载站、后台、安装包、应用内更新全部不受影响**。
- 少一跳回源，页面首字节更快、无 522。
- 归因在 Worker 内闭环，不再依赖跨站上报。
- sharecode 从"每次发版必同步的命门"降级为"仅应急回退时才用到的备用值"。
